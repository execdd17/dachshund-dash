# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Dachshund Dash is a pixel-art endless runner (Chrome Dino-style) starring a dachshund. It's a static site built from native ES modules: `index.html` is a thin shell, `css/style.css` holds all styles, and the game lives in `js/` as vanilla-JS modules drawn onto a `<canvas>`. No build step, bundler, or framework; `package.json` exists only to run the unit tests.

Live at https://execdd17.github.io/dachshund-dash/ (GitHub Pages from this repo).

## Common Commands

```bash
# Run locally — must be served over HTTP (ES modules don't load from file://)
python3 -m http.server 8000      # then visit http://localhost:8000

# Unit tests (Node 18+ built-in test runner, zero dependencies)
npm test                         # or: node --test tests/*.test.js

# Browser verification (headless Chromium via playwright-core; Firestore blocked)
npm run verify:smoke                     # end-to-end run: sounds, menu, tutorial, every encounter, death; [url] to check a deployment
npm run verify:lockstep -- [ref=main]    # update() vs a baseline ref, frame by frame on seeded runs
npm run verify:render -- [ref=main]      # full-frame pixel diff vs a baseline ref; [--save] keeps every frame

# Firestore rules + indexes (Firebase CLI; see firebase/README.md)
npm run firebase:deploy
```

No lint or build tooling. Verify gameplay changes with the tests plus `verify:smoke`. For a refactor (or anything meant not to change behavior), `verify:lockstep` and `verify:render` compare against a git ref and name the first divergent field or frame; an intended change shows up there too, so read the diff rather than chasing zero. The tools (`tools/verify/`) serve the tree themselves on an ephemeral port and find Playwright's Chromium (`$CHROMIUM` overrides). `.claude/skills/verify/SKILL.md` covers driving the game by hand.

### Chrome DevTools MCP (interactive browser access)

A `chrome-devtools` MCP server is registered at **user scope** on the Beelink (in `~/.claude.json`, not this repo): navigate / click / press_key / evaluate_script / take_screenshot / console / network / performance-trace tools against headless Chromium. To re-register:

```bash
claude mcp add --scope user chrome-devtools -- npx -y chrome-devtools-mcp@1.11.0 \
  --headless --isolated \
  --executablePath ~/.cache/ms-playwright/chromium-1228/chrome-linux64/chrome \
  --chromeArg=--no-sandbox --viewport 1280x720 --screenshotMaxWidth 1280 \
  --usageStatistics=false --performanceCrux=false
```

- **Startup**: the server starts with the Claude session (one added mid-session needs a restart; `claude mcp list` shows health); Chromium launches on the first page tool call. Serve the game yourself first — on the Beelink use `python3 -m http.server 8123`, because **port 8000 is taken** there (another service on 127.0.0.1 404s everything, and the python server fails silently).
- **Usage**: call `list_pages` for a `pageId` first. The game is all canvas, so `take_snapshot` shows little — read state with `evaluate_script`, look with `take_screenshot`. `--isolated` gives a fresh profile per session (no stale modules, but no saved high scores/cosmetics/name either).
- **Shutdown**: the browser goes away with the session. Stop the http server with `fuser -k 8123/tcp` — **not** `pkill -f 'http.server 8123'`, which also kills the invoking shell.
- **Limitations**: headless, no audio. `--no-sandbox` is needed because Ubuntu's AppArmor userns restriction aborts sandboxed Chromium — fine for localhost, don't browse untrusted sites with it. The Chromium path is pinned to Playwright's `chromium-1228` (re-register if an update removes it) and the server version to 1.11.0 (bump on purpose). Save screenshots under the OS temp dir.
- **Leaderboard safety**: an automated browser that dies in-game posts a real score to the production leaderboard. Block `firestore.googleapis.com` (Playwright `page.route`) or go offline (MCP `emulate` with `networkConditions: 'Offline'`) after the page loads.

## Architecture

Game logic never touches the DOM, canvas, or Web Audio — everything effectful is injected — so all of `core/`, `systems/`, and `leaderboard/` runs under plain Node for the tests.

### Layers (js/)

- **`config.js`** — every tuning constant. Pure data; a new tunable goes here, never inline.
- **`core/`** — `state.js` (the single mutable state object: `createState()` = session fields + `createRunState()`; `resetRun()` reapplies `createRunState()`), `difficulty.js`, `timeOfDay.js` (score-driven day/night), `color.js`.
- **`systems/`** — gameplay on `(state, …, services)`, with `services = { sfx, music, recordRun }` and injectable `rng`/`now`:
  - `update.js` — the per-frame orchestrator.
  - `control.js` (jump/duck, run start), `spawning.js`, `obstacleTypes.js` (obstacle registry), `birdWalls.js` (multi-bird formations), `collision.js` (dog hitbox + contact resolution), `hearts.js` (spending and regaining hearts), `effects.js` (transient effects list), `giant.js`, `weather.js`, `death.js`, `soundtrack.js` (which music track the game wants), `frenzy.js` (the run's last act, from `FRENZY_AT`).
  - Scenes: `encounters.js` (exclusion rules, scene queue, generic runner `stepScene`), `scenes.js` (registry, phase accessors, `forceScene`), `giantBones.js` (giant mode's bone round), and the scene definitions `tutorial.js` / `chase.js` / `boss.js` / `trampoline.js` / `tunnel.js` (plus `burrow.js`, the dog's moves in the tunnel) / `flight.js`.
- **`render/`** — canvas drawing only: `draw.js` (frame orchestrator + per-scene `SCENE_ACTORS`), `view.js` (world→canvas mapping), `background.js` (sky, hills, ground, decor, rain), `biomes.js` (the scenery's looks as data), `obstacles.js` (`OBSTACLE_LOOKS`), `actors.js` (dog/squirrel + cosmetic overlays), `effects.js` (`EFFECT_DRAWERS`), `tunnel.js` (the tunnel scene's looks and the dog's dive), `flight.js` (the flight scene's cape, wind, bob, and hint), `frenzy.js` (the frenzy's drop, rainbow bursts, inferno, and the score's fire), `hud.js`, `primitives.js`.
- **`audio/`** — `sfx.js` (sounds as data in `TONES`; `createSilentSfx()` derives from the same names) and `music.js` (the tracks as data in `TRACKS`, and a player that follows the wanted one); both have silent test doubles.
- **`assets/`** — `sprites.js` (loading + frame advance for dog/squirrel/bird), `dogFrames.js` (the one dog frame list and `resolveDogFrame`, shared with `tools/`), `images.js`.
- **`cosmetics/`** — `cosmetics.js` (`COSMETIC_DEFS`, calibrated `HEAD_ANCHORS`, equipped-state persistence) and `menu.js` (DOM overlay).
- **`leaderboard/`** — `local.js` (localStorage top list), `global.js` (Firestore boards), `recorder.js` (`recordRun`: placement, local list, global submit for a finished run), `checksum.js`, `ui.js` (HTML table).
- **`input/`** — `input.js` (keyboard/touch/mouse) and `debug.js` (`DEBUG_KEYS`: P slow-mo, C chase, B boss, T trampoline, U tunnel, F flight (sends its cape), G golden hot dog, N next biome, + adds 500 to the score, R rain, H hat). A run that used + is `scoreBoosted` and counts on no leaderboard (`recorder.js`), since debug keys work on the live site..
- **`ui/`** — `startOverlay.js` (start overlay: difficulty, once per page load), `scoreNamePrompt.js` (asks for a name when a score makes the global board), and `howToPlay.js` (the HOW TO PLAY button beside ACCESSORIZE: replays the tutorial).
- **`main.js`** — composition root: builds services, wires the DOM, runs the rAF loop (`update()` then `draw()`).

### Invariants and runtime facts

- **State machine**: `state.gameState` goes `setup` (difficulty only) → `idle` → `running` → `dead` → `running`. Death records the score via `services.recordRun`; a score that makes the global board sets `state.pendingScore`, which opens the name prompt and holds the restart until the player saves or skips (`isBetweenRuns`).
- **Coordinates**: the logical world is `W=800, H=250`. `render/view.js` fits it to the viewport width, pins the ground to the bottom, and turns extra height into sky above y=0 (`view.extraTop`; systems see `state.skyTop ≤ 0`). Use `view.scale`/`view.extraTop`, never a hardcoded scale. A scene can pan the camera by keeping `lift` in its data (`cameraLift`, `scenes.js`): `draw.js` shifts the world by it while the sky, sun, rain, and HUD stay put on screen. The flight pans up; the tunnel dips `TUNNEL_CAMERA_DROP` so its bore clears phone toolbars and home bars, showing `DEEP_EARTH` below the world's bottom edge.
- **One clock**: `main.js` passes the rAF timestamp as `now` to `update()` and `draw()`; everything time-based reads it, and renderers never read the clock themselves. Only the leaderboard (Firestore timestamps) and the tutorial's last-seen record use `Date.now()`, since both span visits. Physics was tuned at a 120Hz baseline: `update()` scales by `dt / DT_BASELINE`, with dt capped at 100ms.
- **Encounters never overlap** (giant mode and the six scenes), including transition phases. Scenes share one slot, `state.scene = { id, phase, …data } | null`; trigger bookkeeping that outlives a scene (`lastEndScore`, boss `lastMilestone`) lives in `state.sceneMemory[id]`. Scenes keep `SCENE_MIN_GAP` of normal play between one another.
- **Scene engine**: a scene definition provides `initialData`, `wantsTurn`, `start`, `phases`, and `quietPhases`; `stepScene` handles the shared lifecycle — request a turn → wait at the head of the FIFO `state.sceneQueue` → `'pending'` until the field clears → phases → `'done'`. The queue is what keeps chase's short cooldown from starving the trampoline. A pending scene stands down if giant mode starts but keeps its turn at the queue front. An optional `jumpsQueue(memory)` puts a turn at the front instead: the boss uses it, so each comes close to its score (`BOSS_AT`: 1000 and 3000; the frenzy brings the third at `FRENZY_AT`, a boss every 2000). There's none at 4000: held up behind other scenes, it often ran right into the frenzy's boss. (Bosses at every 1000, all jumping the queue, made every other scene a boss.)
- **Giant mode**: `state.giantPhase` runs `off → growing → active → shrinking`; `isGiant()` means growing-or-active, and the score multiplier derives from it. `finishGiantTransition` ends grow/shrink at the end of `update()` (drawing never mutates state). Ending grants `GIANT_END_INVULN` i-frames. **Bone round** (`giantBones.js`): while the dog is giant, normal spawning stops and the `GIANT_ROUND` patterns (3 arcs, 2 runs, 2 bobbing bones) come in random order, never one twice running, a hot dog in each gap; a fixed mix keeps every round's bones (23) and pace the same. An arc's bones sit on the giant dog's own jump path at the current speed (`jumpRise`), so one jump timed right takes them all; a run is free at running height; the bobbing bone stays above a running dog. No pattern starts within `GIANT_PATTERNS_STOP_MS` of the end, so the field is clear at the shrink. Hot dogs are eaten automatically (`GIANT_EAT_BONUS`); bones (giant-size `bone` pickups, plus birds and frisbees left on the field, `giant: 'fetch'`) fetched in a row pay `GIANT_BONE_POINTS` × the streak level, capped at `GIANT_STREAK_MAX` (`state.giantStreak`; a bone that gets past breaks it, and jumping one pays no bird bonus). Every eat or fetch pops its points (the `chomp` effect, which also starts the bite pose; they climb in size and color with the streak — there's no HUD meter: a row of bones by the timer read as a bone count), and the end tallies the bonus (`giantFeast`). The giant hitbox scales about the same point as the sprite (`giantPivot`, under the feet), so a jump — drawn twice as high — lifts both; it reaches the drawn feet so it still eats hot dogs. `tests/giantBones.test.js` plays every pattern with bots at several speeds and frame rates — re-run it if jump physics, the giant hitbox, or speed change. Golden pacing (`spawning.js`): at most one golden per stretch between two scenes (`state.goldenSinceScene`, cleared by `markSceneEnd`) and none while a boss waits in the queue (giant mode's points carried a waiting 3000 boss to 4600, into the frenzy's), and `GIANT_COOLDOWN` counts from the later of its spawn and its giant mode's end (`lastGoldenScore`) — one giant mode earns more than the cooldown. Before this, giant mode filled nearly every gap between scenes (5 per 6-minute run, about half the score); `GIANT_SPAWN_CHANCE` is set so it comes about as often as each scene.
- **Hitboxes favor the player**: they sit inside the sprites, never in the air around them. `getDogHitbox` is the dog's bounding box (used for placement checks such as the trampoline bounce and the tutorial's gaps); `checkCollision` uses `getDogHurtboxes`, which in the grounded run pose lowers the box's rear to the back line (`DOG_HITBOX_RUN_REAR`, measured from the run frames), so standing up under a bird that's past the head doesn't hit. Birds' hitboxes stop short of their tail feathers (`BIRD_INSET`). The dog's shaping only lowers the top of its rear on the ground, so every jump clearance is unchanged; the bird trim only makes clearing a bird slightly more forgiving (the bird-wall tests hold either way).
- **Hearts**: `state.startingHearts` comes from the difficulty slider (`DIFFICULTY_LEVELS`, locked per session). A non-fatal hit spends a heart, knocks the obstacle away, and grants `HEART_HIT_INVULN` i-frames; the last heart kills. Boss catches bypass hearts. The only way back is the trampoline's heart pickup (`hearts.js`): it restores one, never past `startingHearts`; with all full it pays `HEART_FULL_BONUS` instead.
- **Tutorial scene** (`systems/tutorial.js`): runs at the start of a run while `state.tutorialPending`, which `main.js` sets from `isTutorialDue` (a device's first visit, `TUTORIAL_REFRESH_MS` since last seen, or a newer `TUTORIAL_VERSION` — bump it when the controls or the tutorial change, not on every deploy) and the HOW TO PLAY button sets. Three steps (chocolate bar: jump; `tower`: double jump; bird wall: duck), each a `practice` obstacle — collision knocks it away without a heart and the step repeats (TRY AGAIN). A prompt appears, and time slows to `TUTORIAL_SLOW_SCALE`, inside each step's `TUTORIAL_GAPS` window; only an action taken while prompted counts, and a jump prompts only with the dog grounded (the jump that starts a run must not count). The windows were measured by sweeping press timings — re-measure if jump physics, speed, or the tower change (`tests/tutorial.test.js` plays it with a bot at several reaction times). The score stays 0 (`scoreless`).
- **Tower** (`tower` obstacle, from score `SPAWN_MIX.tower.after`): too tall for one jump, so it's the double-jump obstacle. It grows with speed (`towerSizeFor`): `TOWER_BARS.short` (5) below `TOWER_TALL_FROM_SPEED`, forgiving of second-press timing, then `.tall` (6), which a faster single jump would otherwise clear. The tutorial gets the short one at its starting speed. Measured by sweeping jump timings against speed — re-sweep if jump physics or `MAX_SPEED` change.
- **Spawn patterns** ease in: none before `PATTERN_FIRST_AT`, then `patternChance` ramps from `PATTERN_CHANCE.start` to `.full` by `.fullAt`.
- **Trampoline scene**: reps scale with speed (`getTrampLayout`) so the thorn patch can't be double-jumped; landing on the island auto-bounces. Thorns are terrain — they cost a heart but stay, and a rising dog passes over them. The obstacle cull is right-edge-based so the wide trampoline doesn't vanish early. A rep with `heart` in `TRAMP_REPS` (the last one) floats a heart pickup just above the bounce's apex, a fixed time after the bounce (`leadFactor * speed` past the island): the bounce resets the double jump, and only a second jump pressed near the apex reaches it. Its placement was measured by sweeping landing spots and press timings at 60/120/144Hz — re-sweep if jump physics, `TRAMP_BOUNCE_VY`, or hitboxes change (`tests/trampoline.test.js` asserts the bounce alone falls short and every landing spot keeps a ≥8-frame window).
- **Tunnel scene** (`tunnel.js`, from `TUNNEL_FIRST_AT`): a tunnel under the path with holes `TUNNEL_BEAT_FRAMES` apart in time (spacing scales with speed; 90 frames proved too quick for kids). Duck over a hole drops the dog in (`burrow.js`); it stays down while duck is held, pops up at the next hole once duck is let go, and jumping under a hole pops out with a full jump. Each hole works once, so a duck pressed early can't drop the dog back into the hole it just left. A layout (`TUNNEL_LAYOUTS`, never the same twice running) is a list of `TUNNEL_STRETCHES`, one per gap between holes, each with the layer it `needs`: a hedge (too tall for any double jump) needs the tunnel, a rock needs the surface, and open stretches leave the tunnel safe and empty while the surface pays (bones over a chocolate bar, a bird's jump bonus). The layers are pure geometry: in the tunnel the dog's hurtbox drops `TUNNEL_DEPTH`, below every surface hitbox, and rocks sit below anything a surface dog reaches. Rocks are drawn pale with a dark outline against the dark bore (nothing else down there is pale), with a yellow "!" `rockSign` (scenery) planted in the path above each one. The camera dips while the tunnel is ahead and eases back up before the scene ends. Every run flashes HOLD ↓ over its first tunnel's first hole until the dog first drops in (`state.tunnelHintPending`, run-scoped). `tests/tunnel.test.js` plays every layout with bots at several speeds and frame rates — re-run it if jump physics, speed, or the spacing change (it also checks the camera dip).
- **Flight scene** (`flight.js`, from `FLIGHT_FIRST_AT`): a Hero Cape floats in at running height (a ducking dog still gets it; only a jump timed over it misses, and a miss retries after half of `FLIGHT_COOLDOWN`). Grabbing it puts the `cape-hero` outfit on the dog for the flight (`withFlightCape`), sets `dog.flying` (no gravity: the scene moves the dog), and pans the camera up so the three `FLIGHT_LANES` sit centered between the HUD and the screen bottom on any screen (taller screens pan less). Jump moves up a lane, duck down one. `FLIGHT_GATES` bird gates come `FLIGHT_GATE_BEAT_FRAMES` apart in time: the first few block one lane, the rest all but one, sometimes with a bone in an open lane; gate birds are `aerialWall` (no jump bonus). Every run flashes ↑ ↓ above the dog until its first lane change (`state.flightHintPending`). Landing glides back to the path and the cape flies off. `tests/flight.test.js` flies every gate with bots at several speeds and frame rates and checks the camera centering — re-run it if the lanes, hitboxes, speed, or the spacing change.
- **Layout**: full-bleed everywhere; the CSS splits on `touch-device`. Touch landscape is game-only, touch portrait shows a rotate prompt + leaderboard, desktop scrolls to hints + leaderboard below the game. Installable as a home-screen PWA (`manifest.json`). `?app=1` is a no-op kept for old links.
- Music needs a user interaction to start (autoplay policy): `music.attachAutoplayUnlock()`.
- **Frenzy** (`systems/frenzy.js`, looks in `render/frenzy.js`): the run's last act, to match the frantic music. From `FRENZY_AT` (5000), at the first moment the field is free (giant mode over, no scene past `pending`), the drop: everything on screen bursts into a rainbow, the screen flashes, a shockwave rolls out, the camera shakes, FRENZY! comes up, and the boss starts in that same frame (`forceScene`, which clears the field: it kicks the frenzy off, so no queue, no gap between scenes, no golden hot dog sneaking in first; a scene waiting in `pending` goes next instead). `FRENZY_DROP_CALM` px pass before the next spawn. `state.frenzyAt` records the drop, and the music and the score's fire key off it. Scenes marked `skipsFrenzy` — the boss (beyond that opener: at top speed it's nearly unwinnable) and the tunnel (doesn't fit the theme) — never ask for a turn again, and lose any queued one. From then on, outside giant mode (scenes included), a hazard wholly behind the dog bursts (after the bird bonus check, so a jumped bird still pays), and the inferno plays: a burning horizon, the path burning behind the dog (a comet tail while it flies), speed lines (while it flies, the flight's own wind lines, set alight, instead: one set of lines), embers. Only the drop changes what the dog faces. `MAX_SPEED` is 6.75, reached at 7500 (it was 6.5 at 7000), so speed keeps climbing well into the frenzy. Tests that need top speed start past the drop (`frenzyAt = 1`), since its score is past `FRENZY_AT`; `tests/frenzy.test.js` covers the frenzy.
- **Music**: `update()` hands `soundtrackFor(state)` to `services.music.follow()` every frame, between runs too, and the player switches only when it changes — nothing else switches tracks. From the frenzy's drop (below) the rest of the run gets `frenzy` ("The Clockwork Gauntlet"), giant mode included — cutting away from it was jarring; before that, giant mode gets `giant`; otherwise, and between runs, `main`, which rewinds the others so each run hears them from the start. A switch fades the old track out over `MUSIC_FADE_MS`, then the next one in (a cut at game over was jarring); giant mode cuts in at once, from the top. Volume runs through a Web Audio gain per track because iOS ignores an audio element's volume (no fades, and no mix: music played at full volume there before). With it, flames rise from the score (`drawScoreFire`, `render/frenzy.js`), so the player sees why the music changed. The fire is a speedometer from there (speed is a fixed function of score): taller, hotter, and thicker with embers as speed climbs, white-hot at the core at `MAX_SPEED`, with a flare at the catch and at the max. Its MP3 is trimmed at frame boundaries (no re-encode) to the end of the final chord's ring-out, because the original's trailing silence left a gap at every loop. The main track is a 320 kbps MP3 encoded from the original WAV (in git history).

### Extending the game

- **Bones** are the game's one collectible (`bone`, one look in `render/obstacles.js`): +`BONE_POINTS` anywhere, the streak in giant mode. Scenes size them (the tunnel and flight use the default; giant mode `GIANT_BONE_W` × `GIANT_BONE_H`) — a new reward should be a bone, not a new item.
- **Biome** (cosmetic): one entry in `BIOMES` (`render/biomes.js`; spread `MEADOW` for the parts it keeps): `[day, sunset, night, dawn]` palettes for the sky, clouds, path, and grass, the hill layers (same count in every biome, each with a shape function, a scroll rate, and optional `details` drawn over the fill — the autumn ridge colors its trees that way), and a `decor` drawer for the `state.flowers` spots. `background.js` draws only from it, so nothing else changes. Each biome lasts `BIOME_CYCLES` day cycles and hands over to the next across the last one's full night (colors blend, hills morph, decor crossfades); the N debug key skips ahead (`state.biomeSkip`, never the score). `tests/biomes.test.js` checks the schedule and that every biome is complete; `verify:render` has a frame for every biome at each time of day.
- **Bobbing**: any obstacle made with `bob: { amp, period, phase }` moves up and down around its starting y on game time (`stepBob`, run by `update()`), hitbox included.
- **Obstacle type**: an `OBSTACLE_TYPES` entry (`systems/obstacleTypes.js`: size/y, hitbox `inset`, `contact` — `hazard`/`terrain`/`pickup`/`none` — plus `giant: 'eat'|'bonk'` for hazards, `collect` for pickups (a `COLLECT_ACTIONS` entry in `collision.js`), and `aerial`) and an `OBSTACLE_LOOKS` entry (`render/obstacles.js`: `normal`, optional `chase`/`giant`). Build with `makeObstacle`; spawn via a `SPAWN_KINDS` entry or from a scene. `tests/obstacleTypes.test.js` catches a missing registration or look.
- **Spawn mix and patterns**: `SPAWN_MIX` (config) sets the solo mix; `SPAWN_PATTERNS` (`spawning.js`) are close-gap multi-beat sequences; the bird wall (`birdWalls.js`) carries `aerialWall` and earns no jump bonus. Its look must match what it takes: the stack (a three-bird column, also the tutorial's duck step) can only be ducked, which `tests/birdWalls.test.js` holds against the real physics at every speed. (A ∧ triangle was removed: it asked nothing a lone bird doesn't, with a harder jump and no bonus.) In chase, aerials become acorns at `chaseAcornY()`, the one source for their height in both hitbox and draw.
- **Scene**: a definition object in its own file, added to `SCENES` (`scenes.js`), plus `SCENE_ACTORS` (`render/draw.js`) if it draws actors. `start` and the phases get the frame's `{ scale, services, now, rng }`. Optional `timeScale(scene)` slows game time and `scoreless` stops distance points (see the field list in `encounters.js`). Scene tests use `getScenePhase`/`setScenePhase`, never raw state.
- **Effect**: an `EFFECT_KINDS` entry (`systems/effects.js`: lifetime + optional `step`) and an `EFFECT_DRAWERS` entry (`render/effects.js`); spawn with `addEffect(state, kind, now, props)`.
- **Run-scoped state**: add it to `createRunState()`; a test checks `resetRun` restores exactly that set.
- **Sound**: one `TONES` entry in `audio/sfx.js`; `tests/audio.test.js` checks every `sfx.play*` call exists.
- **Music track**: a `TRACKS` entry (`audio/music.js`) and a rule in `soundtrackFor` (`systems/soundtrack.js`); `tests/soundtrack.test.js` checks the choice, the files, and the player.
- **Cosmetic item**: an entry in `COSMETIC_DEFS`. *Anchor items* (hats, sunglasses) are one PNG placed by `HEAD_ANCHORS` + `SLOT_ANCHOR_OFFSET` (+ optional per-item `offset`). *Per-frame items* (shoes, body outfits) are one full-size overlay per dog frame plus the bite sheet, generated by `tools/gen-shoes.cjs`, `gen-tutu.cjs`, or `gen-outfits.cjs` (`node tools/gen-X.cjs . [previewDir]`; the preview dir gets alignment composites). Those share `tools/spritelib.cjs` and the frame list in `js/assets/dogFrames.js`. Five sunglasses come from `tools/gen-glasses.cjs`.
- **Tests**: `tests/*.test.js` with `tests/helpers.js` (fake storage, sequence rng, silent services). Keep DOM-touching modules (input.js, ui/, menu, main) out; importing a render module for its tables is fine.

### Leaderboards

- **Local**: top scores in localStorage (`MAX_HIGH_SCORES`); surfaced only as the `HI` figure in the HUD.
- **Global**: Firestore `scores`, one board per difficulty, top `GLOBAL_MAX_SCORES` (25). **Reads and writes are kept to a minimum (free tier)**: after setup the game fetches only the player's board (≤25 docs, from the server — an offline cache would look empty and place every score); other tabs load on demand, once each. Placement reads the cached session board, so death makes no reads; a finished run refetches it only when older than `GLOBAL_REFRESH_MS`, and the idle game never polls. Nothing asks for a name up front: only a score that places prompts for one (prefilled with the last name saved on the device, `PLAYER_NAME_KEY`), and SAVE is the only write — one doc, inserted into the cached board without a reread. SKIP or a blank name writes nothing, so no `PLAYER` entries. Ties rank below existing entries. Submissions carry a salted checksum (`checksum.js`) as friction, not security. Composite index (`firestore.indexes.json`): `difficulty` ASC, `score` DESC, `timestamp` ASC.
- The Firebase config in `js/firebase.js` is a public web config — not a secret, not a security boundary.
- **Rules are strict**: `firestore.rules` allows exactly `name, score, difficulty, timestamp, checksum` with type/range checks. **Any change to the submitted doc needs `firestore.rules` (and indexes if relevant) updated and `npm run firebase:deploy`**, or submissions fail with PERMISSION_DENIED (only a `console.warn` in-game). Admin scripts — bulk deletes (`firebase/delete-scores-by-*.mjs`) and trimming each board to its top 25 (`firebase/prune-scores.mjs`) — are documented in `firebase/README.md`; the service-account key is git-ignored.

### Input

- Desktop: Space/Up jump (twice for a double jump), Down/S duck, click jumps.
- Touch: the right side jumps, holding the left `DUCK_ZONE_RATIO` (40%) ducks (tracked per finger, so a jump tap doesn't end it); the speaker icon top-left toggles music.
- Duck is a held input (`state.duckHeld`), applied every frame by `applyDuck`: the dog ducks whenever duck is held and it's grounded (and always while it crawls through the tunnel), so holding it through a jump ducks on the landing frame, before collision. While the dog flies, jump and duck presses move it a lane instead.
- Fast-fall: a duck *pressed* mid-air cuts any rise to `FAST_FALL_VY` and multiplies gravity by `FAST_FALL_GRAVITY_MULT` until landing, release, a double jump, or a trampoline bounce (`dog.fastFalling`). A duck held since the ground (into a bounce) doesn't trigger it.
